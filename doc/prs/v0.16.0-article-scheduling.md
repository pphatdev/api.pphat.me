# feat: schedule article publication with Asia/Phnom_Penh timezone (v0.16.0)

<!-- Draft PR body for develop → master. Copy the sections below into the GitHub PR description. -->

## Summary
- Adds article publish scheduling. Authors can now `POST /v1/api/articles` with a `publishAt` timestamp (Asia/Phnom_Penh, +07:00) and the article stays hidden from the public list until the scheduled time passes.
- Introduces an `is_public` flag on articles that acts as the sole public-visibility gate. The existing `published` flag is retained as the "author-declared ready" signal; both must be `1` for the article to appear in the public list.
- Wires a Cloudflare Cron Trigger (`*/5 * * * *`) that promotes any `published=1, is_public=0, publish_at <= now()` rows to public each tick.
- All authenticated endpoints remain authenticated — no change to the auth surface introduced in v0.15.0.

## Motivation
Content creators need to draft a post, set a release window, and let it go live automatically without keeping a browser tab open. Wire timestamps are always Asia/Phnom_Penh (UTC+7, no DST) because that's where the team operates, so `publishAt: "2026-08-15 09:00"` means 09:00 local — no timezone bookkeeping on the client.

## Notable changes

### Schema
- `migrations/0017_articles_scheduling.sql`
  - `articles.is_public INTEGER NOT NULL DEFAULT 0`
  - `articles.publish_at TEXT NULL` (stored as UTC ISO)
  - Composite index `idx_articles_scheduling(is_public, publish_at)` for the cron scan
  - Backfill: existing `published=1` rows get `is_public=1` so no existing article disappears

### Runtime
- `apps/shared/helpers/tz.ts` — fixed-offset Phnom_Penh helper:
  - `parsePhnomPenhToUtc(input)` — accepts full ISO (any offset), bare local (`YYYY-MM-DD HH:mm[:ss]`), or ISO-without-offset; returns UTC ISO
  - `formatUtcAsPhnomPenh(utcIso)` — reverse; always emits `+07:00`
- `apps/modules/articles/articles.controller.ts` — `normalizeSchedulingFields()` runs on create/update; rejects malformed `publishAt` (422) and enforces `isPublic: boolean`.
- `apps/modules/articles/articles.repo.ts`:
  - `findAll()` public path now requires `is_public = 1` in addition to `published = 1`.
  - `insertArticle()` persists `is_public` and `publish_at`; auto-sets `is_public=1` when `publish_at` is in the past on create.
  - `promoteScheduled()` — the cron target. Uses `datetime(publish_at) <= datetime('now')` so ISO/space-format mismatch doesn't bite.
  - `hydrate()` now emits `isPublic: boolean` and `publishAt: string | null` (formatted as Phnom_Penh).
- `apps/app.ts` — exports `{ fetch, scheduled }`. The `scheduled` handler wraps `promoteScheduled()` in `ctx.waitUntil` and logs the count of promoted rows.
- `wrangler.jsonc` — `triggers.crons: ["*/5 * * * *"]`.

### Docs
- `doc/features/articles.md` — new "Publish scheduling (Asia/Phnom_Penh)" section explaining the two accepted `publishAt` formats, the auto-promote flow, and the filter semantics.

## API contract (unchanged shape, additive fields)

**Request** (create/update):
```jsonc
{
  "title": "My Article",
  "slug": "my-article",
  "description": "…",
  "published": true,           // author-declared ready
  "isPublic": false,           // optional; direct visibility gate
  "publishAt": "2026-08-15 09:00" // optional; Phnom_Penh local — or full ISO
}
```

**Response** (new fields on `Article`):
```jsonc
{
  "published": true,
  "isPublic": false,
  "publishAt": "2026-08-15T09:00:00+07:00"
}
```

## Rollout notes

- Migration `0017` is additive and non-destructive: `is_public` defaults to `0`, then the backfill sets it to `1` for every already-`published=1` row. Zero existing public articles get hidden.
- Cron trigger will not run in `wrangler dev` — test locally by calling `ArticleRepository.promoteScheduled()` directly (as the feature test does) or by hitting `/__scheduled?cron=*/5+*+*+*+*` on `wrangler dev --test-scheduled` if you want to exercise the wire.
- No client-side changes required; existing callers that don't send `publishAt` / `isPublic` get identical behavior to before (article defaults to `is_public=0`, so if you want it immediately public you must send `isPublic: true` on create or set `published+is_public` via the SQL migration — **watch for this in QA**).
